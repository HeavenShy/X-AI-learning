# mistake-review Specification

## Purpose

让用户在“复习”标签里看到自己闯关时答错、还没掌握的题，重新作答；答对即视为掌握并从错题本移除。

## Requirements

### Requirement: 错题来源
系统 SHALL 把当前用户已完结的每一话中、服务端判定为答错（含未作答）的题，视为该用户的错题。只出题未完结的话不产生错题。错题只对其所属用户可见。

#### Scenario: 完结一话后答错的题进入错题本
- **WHEN** 用户完结一话 5 道题，其中第 2、4 题服务端判为答错
- **THEN** 该用户的错题列表包含这两道题，不包含其余 3 道

#### Scenario: 未完结的话不产生错题
- **WHEN** 用户只生成了题库、没有提交答题结果
- **THEN** 错题列表中没有该题库的题

#### Scenario: 看不到别人的错题
- **WHEN** 用户 A 有错题，用户 B 请求错题列表
- **THEN** B 得到的列表不包含 A 的任何错题

#### Scenario: 历史错题自动出现
- **WHEN** 本功能上线前用户已经完结过有答错题的话
- **THEN** 这些题出现在错题列表中，无需用户额外操作

### Requirement: 错题列表
系统 SHALL 通过 `GET /api/v1/review/mistakes` 返回当前用户所有未掌握的错题。每项包含所属话的 `quiz_id` 与标题、完整题目（题型、题干、选项、答案、讲解、知识点）、上次的错误答案、累计答错次数、首次答错时间（ISO 8601 UTC）。列表按话的完结时间从新到旧排列，同一话内按题目原顺序排列。

#### Scenario: 返回未掌握的错题
- **WHEN** 已登录用户有 3 道未掌握的错题，请求错题列表
- **THEN** 返回 code 0，`items` 含这 3 道题，`total` 为 3

#### Scenario: 首次答错次数为 1
- **WHEN** 一道题只在闯关时答错过、还没有重做
- **THEN** 该项的答错次数为 1，上次的错误答案是闯关时选的选项

#### Scenario: 没有错题
- **WHEN** 已登录用户没有任何未掌握的错题
- **THEN** 返回 code 0，`items` 为空数组，`total` 为 0

#### Scenario: 未登录
- **WHEN** 请求不带有效登录凭证
- **THEN** 返回 code 4010

### Requirement: 重做错题判题
系统 SHALL 通过 `POST /api/v1/review/answer` 接收 `quiz_id`、`question_id`、`selected_answers`，按服务端存档的题目答案判题（与闯关判题规则一致：选项去空格、不区分大小写、去重后与答案完全相同才算对，空选择算错），返回是否答对与正确答案。

#### Scenario: 答对
- **WHEN** 用户对一道未掌握的错题提交与正确答案一致的选项
- **THEN** 返回 code 0，`is_correct` 为 true

#### Scenario: 多选题漏选算错
- **WHEN** 多选题正确答案为 A、C，用户只提交 A
- **THEN** `is_correct` 为 false

#### Scenario: 前端判题结果不被采信
- **WHEN** 请求中附带的答案与存档答案不一致
- **THEN** 服务端按存档答案判题，判为答错

#### Scenario: 不是自己的错题
- **WHEN** 提交的 `quiz_id` / `question_id` 不属于当前用户的错题（不存在、属于别人、或闯关时就答对了）
- **THEN** 返回 code 4040，不记录任何状态

#### Scenario: 未登录提交
- **WHEN** 不带有效登录凭证提交
- **THEN** 返回 code 4010

### Requirement: 答对后移出错题本
重做答对时，系统 SHALL 把该题标记为已掌握，之后的错题列表不再返回它。已掌握的题再次提交时 SHALL 仍正常判题并返回结果，不改变已掌握状态。

#### Scenario: 答对后从列表消失
- **WHEN** 用户重做一道错题并答对，然后重新请求错题列表
- **THEN** 列表中不再有这道题，`total` 减 1

#### Scenario: 重复提交已掌握的题
- **WHEN** 用户对已掌握的题再次提交（如网络重试）
- **THEN** 返回判题结果，该题仍为已掌握，不会重新进入列表

### Requirement: 答错后留在错题本
重做答错时，系统 SHALL 保留该题在错题列表中，答错次数加 1，并把“上次的错误答案”更新为本次提交的选项。

#### Scenario: 再错一次
- **WHEN** 一道答错次数为 1 的错题被重做且答错（选了 B）
- **THEN** 之后的错题列表中该题答错次数为 2，上次的错误答案为 B

### Requirement: 重做不发奖励
重做错题 SHALL NOT 增加用户的经验值或金币，也 SHALL NOT 改变任何一话已有的答题记录、正确率与报告。

#### Scenario: 答对不加经验
- **WHEN** 用户重做错题答对
- **THEN** 用户资料中的累计经验与金币不变，对应那一话的历史记录正确率不变

### Requirement: 复习页展示错题本
复习标签页 SHALL 按话分组展示错题（组标题为话的标题和该组题数），每道题显示题型标签、题干和“错 N 次”。每次切到复习标签时 SHALL 重新拉取列表。没有错题时显示空状态并提供“去闯关”按钮；加载失败时显示失败提示与重试入口。

#### Scenario: 分组展示
- **WHEN** 用户有来自 2 话的错题
- **THEN** 复习页显示 2 个分组，每组列出该话的错题及题型、题干、答错次数

#### Scenario: 空状态
- **WHEN** 用户没有未掌握的错题
- **THEN** 复习页显示空状态文案和“去闯关”按钮，点按钮切到闯关标签

#### Scenario: 答对返回后列表已更新
- **WHEN** 用户在重做页答对后返回复习页
- **THEN** 那道题已不在列表中

### Requirement: 重做页作答
点开一道错题 SHALL 进入重做页，以闯关页相同的交互作答（单选、判断点一下即判；多选选好后提交），判题后展示对错标记、正确答案、讲解与知识点，并提示上次的错误答案。答对时提示“已移出错题本”并提供返回复习；答错时提供“再做一次”与返回复习。提交保存失败时 SHALL 提示用户，且该题不从列表移除。

#### Scenario: 答对提示
- **WHEN** 用户在重做页答对
- **THEN** 页面显示答对结果和“已移出错题本”，不显示经验金币奖励

#### Scenario: 答错可再做
- **WHEN** 用户在重做页答错后点“再做一次”
- **THEN** 选项恢复为未作答状态，可以重新选择

#### Scenario: 保存失败
- **WHEN** 提交重做答案的请求失败
- **THEN** 页面提示没保存上，返回复习页后该题仍在列表中
